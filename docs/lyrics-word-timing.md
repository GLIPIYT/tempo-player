# Тайминги слов: MVP

Реализовано в основной ветке после v1.4.2. Установщик v1.4.2 этой доработки не содержит.

## Как включить

В настройках оформления лирики выбрать заполнение **«По словам»**. Готовые тайминги из расширенного LRC используются автоматически. Для получения недостающих таймингов из доступного аудиофайла включить существующее **«Углубленное анализирование лирики»**.

Сам выбор режима «По словам» не разрешает скачивание модели или аудио. Глубокий анализ остаётся отдельной настройкой; он использует уже предусмотренную модель Whisper tiny_timestamped, без добавления новой модели или сервиса. При включении глубокого анализа существующий механизм может загрузить модель, если её ещё нет.

## Откуда берутся времена

1. **Расширенный LRC или сохранённая лирика со словами.** Приоритет имеют исходные времена слов. Фрагменты, разделённые внутри одного слова, объединяются в одно отображаемое слово. Если известны только начала, конец слова для подсветки берётся из следующего начала или конца строки; это предполагаемый конец, а не измеренное окончание вокала.
2. **Сохранённые результаты глубокого анализа.** Уже распознанные аудиофрагменты проверяются повторно для выбранного текста. Совпадение должно содержать всю строку в правильном порядке. Регистр, пунктуация и `ё/е` не мешают сопоставлению. Повторяющийся припев ищется рядом с таймингом соответствующей строки; неоднозначные результаты отбрасываются.
3. **Новый глубокий анализ.** Если он разрешён, в режиме «По словам» анализируются также строки с готовым концом, но без пригодных таймингов слов. Входом служит зарегистрированный локальный или уже закэшированный файл, а не произвольный онлайн-поток. Планировщик обрабатывает короткие окна, сохраняет результат и выдерживает паузы между вычислениями. Работа не обязана завершиться за одно прослушивание.
4. **Текстовая оценка.** Если надёжных данных нет, длительность строки распределяется по приблизительным слогам. Короткие союзы, предлоги и артикли получают меньше времени. Для содержательных слов учитываются вероятное растяжение конечной гласной, явно растянутые буквы, пунктуация и окончание фразы. Это слабые текстовые подсказки: гласная сама по себе не доказывает протяжённый звук. Неполные распознавания и несовпадающий текст не выдаются за точные тайминги.

Повторы анализируются по всему выбранному тексту. Для повторяющейся фразы с совпадающими словами можно перенести относительный рисунок уже известных времён слов; результат остаётся **оценкой**. Несовместимые длительности или расходящиеся исполнения не смешиваются. Два согласующихся точных окончания одинаковой фразы также помогают оценить её конец в другом повторе. Ручные и исходные окончания не заменяются. Семантических ярлыков «припев»/«куплет» этот механизм не назначает.

Исходный текст не заменяется распознанным. Ручные окончания строк сохраняют приоритет. Автоматические слова используются только в пределах действующей строки и аудиофайла. ASR даёт оценку времён, а не гарантию точности до миллисекунды.

## Что видно при воспроизведении

- Слово выделяется по исходному/распознанному времени начала, а при их отсутствии — по текстовой оценке, независимо от ширины шрифта. Пройденные слова остаются светлее будущих.
- Если у слов известны окончания и между ними есть тишина, текущее свечение снимается на этот промежуток. Новые строки с нотами между каждым словом не создаются.
- Исходные тайминги одновременно поющихся строк сохраняются независимо: одновременно могут выделяться слова двух голосов. Неоднозначное ASR-сопоставление таких строк в MVP пропускается.
- Перемотка, смещение и скорость лирики используют общую временную шкалу. Смещение не прибавляется к слову повторно.
- Поздний результат анализа не переигрывает уже начавшуюся строку. Будущие строки уточняются сразу; для уже начавшейся результат применяется при следующем проходе или перемотке назад. Это сохраняет устойчивость подсветки и прокрутки.

## Хранение и нагрузка

Аудиофрагменты распознавания сохраняются существующим кэшем по отпечатку аудио и версии анализа/модели. При повторном открытии соответствующие слова восстанавливаются из этих данных без нового распознавания. Смена текста или провайдера требует нового сопоставления; старые результаты другого выбора лирики не подставляются.

Сопоставление и проекция смещения мемоизируются. Обновления таймера с неизменившимся анализом не пересчитывают весь список строк. В кадре меняются классы только тех слов активной строки, у которых изменилось состояние; непрерывная перерисовка всего текста через React не добавляется.

## Ограничения MVP

- Автоматическое сопоставление рассчитано на русский и английский текст и полные строки минимум из двух распознанных слов.
- Вся строка должна попасть в один пригодный фрагмент. Слова у обрезанного края, наложенные голоса, длинные фразы и расхождения распознавания дают резервное заполнение. Несколько фрагментов вслепую не сшиваются.
- Времена исходной строки должны примерно соответствовать аудио. Сильно сдвинутый исходник, даже исправленный большим пользовательским смещением, может не пройти каноническое ASR-сопоставление.
- Фрагмент исходного LRC, включающий сразу несколько отдельных слов без внутренних меток времени, не определяет начала этих слов. Для него действует текстовая оценка, если анализ не дал пригодную замену.
- Существующие ограничения входного файла сохраняются: до 64 МиБ и 600 секунд, с ограничением памяти декодирования. Доступность файла и включённая настройка сами по себе не гарантируют успешного распознавания пения.
- Это подключение готовых времён и консервативное ASR-сопоставление. Отдельный вокальный детектор, forced alignment всей песни и редактор времён каждого слова в этот MVP не входят.

## Маленькая вокальная модель

Проверена применимость [FireRedVAD AED](https://huggingface.co/FireRedTeam/FireRedVAD/tree/main/AED): около 589 тысяч параметров, файл весов около 2,37 МБ, Apache-2.0. Модель выдаёт вероятности речи, пения и музыки по кадрам; пение и музыка могут присутствовать одновременно. Она может дать дополнительную опору для границ фразы, но не определяет, какое слово сейчас поётся.

В [официальном runtime](https://github.com/FireRedTeam/FireRedVAD/tree/main/runtime) есть NCNN-путь для AED. Документированный ONNX/Rust-пример относится к streaming VAD, а готовый официальный AED ONNX-путь для текущего движка Tempo не подтверждён. Эта модель в приложение пока не добавлена. Опубликованную метрику бинарного voice/non-voice нельзя считать проверкой точности таймингов русских песен.

## Проверки

Автоматические тесты покрывают исходные и распознанные слова, слоговые фрагменты, пунктуацию, повреждённые данные, повторы припева, кэш, смену текста, смещение, скорость, перемотку, одновременные строки и позднее уточнение. Дополнительно проверяется настоящий `SyncedView` в браузере без запуска dev-плеера. Эти проверки подтверждают передачу и использование таймингов; качество распознавания на произвольной музыке ими не измеряется.
