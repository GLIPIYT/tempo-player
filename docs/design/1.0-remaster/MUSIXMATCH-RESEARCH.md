# Musixmatch: проверка неофициальных endpoint'ов

**Проверено:** 24 сентября 2026 года. Запросы выполнялись к публичным endpoint'ам, без API-ключей и без сохранения токенов/текстов песен в репозитории.

## Результаты проверок

| Endpoint | Результат |
| --- | --- |
| `apic-desktop.musixmatch.com/ws/1.1/token.get` | Выдаёт анонимный токен: API status 200, длина 56 символов, не начинается с `UpgradeOnly`. |
| `apic-desktop…/macro.subtitles.get` | Для `Skyfall` / Adele, альбома Skyfall и длительности 286 секунд ответ несколько раз содержал метаданные **NOKIA — Drake**, длительность отсутствовала. Добавление `q_artists`, `f_subtitle_length` и удаление `format=json` не меняли результат. |
| `apic-desktop…/macro.search` | Запросы `Skyfall Adele` и `Drake NOKIA` с тем же токеном возвращали один и тот же список, начиная с `Salimos a Buscarte — Bad Bunny` и `Mix Rap 2 — Daddy Yankee`. API сообщал 200, но результаты не соответствовали запросам. |
| `apic-desktop…/track.subtitle.get` | Запросы по `track_id` и `commontrack_id` из ответа Musixmatch вернули API status 404. |
| Прямой `apic-desktop…/matcher.track.get` | 404 `endpoint not found`; этот matcher вызывается внутри macro-ответа, отдельный путь на проверенном хосте не доступен. |
| `apic.musixmatch.com/ws/1.1/token.get` | API status 401, hint `upgrade`; пригодного анонимного токена нет. |
| `api.musixmatch.com/ws/1.1/token.get` | API status 401, токен без API-ключа не выдаётся. |
| `www.musixmatch.com/ws/1.1/token.get` | HTTP 503 с TLS-ошибкой `hostname doesn't match against certificate`. |

## Что это значит для Tempo

Самый вероятный класс причины — сбой обработки/маршрутизации параметров поиска или некорректное кэширование на стороне неофициального `apic-desktop` API. Это вывод из повторяемого результата на разных запросах; по доступным ответам нельзя достоверно различить ошибку matcher'а, кэш CDN и ограничение guest API.

HTTP 200 нельзя считать доказательством правильного результата. В текущей интеграции Tempo сравнивает название и исполнителя с запрошенными метаданными и отвергает несовпадение до использования текста. Поэтому NOKIA не должен подменять Skyfall; провайдер остаётся неудачным и срабатывает переход к другим источникам.

## Другие найденные варианты

- Текущий публичный community-клиент описывает тот же token-based flow через `apic-desktop` и предупреждает, что endpoint неофициальный, подвержен лимитам и изменениям: [musixmatch-freeAPI](https://github.com/ybenyedder/musixmatch-freeAPI). Его параметры совпадают с текущим запросом Tempo; живой ответ в этой проверке был некорректным.
- В опубликованной документации Musixmatch для Lyrics API указан API key как способ авторизации: [официальная коллекция Lyrics API](https://www.postman.com/musixmatch-dev/musixmatch-apis/collection/pqm8o6w/lyrics-api). Бесплатный ключ без ограничений тут не подтверждён.
- Старые клиенты используют HMAC-подписанный `www.musixmatch.com/ws/1.1`; в этой проверке он вернул TLS/503. Репозиторий выше также сообщает о такой ошибке.
- Код стороннего iOS-твика описывает отдельный host и мобильный способ подписи; он не является анонимным drop-in API. Не включать его в Tempo без подтверждённой авторизации и повторяемой корректной выдачи.

## Решение

Рабочий бесплатный анонимный Musixmatch endpoint в этой проверке не найден. Не менять текущую интеграцию на другой частный endpoint по одному HTTP 200. Оставить проверку соответствия metadata и fallback-провайдеры. Если позже появится endpoint, который возвращает правильные результаты несколько раз для разных треков, заменить только сетевой адаптер и повторить проверку до публикации.
