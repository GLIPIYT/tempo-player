# Сервисы и источники Tempo 1.0

Проверено 25 сентября 2026 года. Возможности публичных API, частных endpoint и замеры сети отмечены отдельно: последние два могут измениться без предупреждения.

## TheAudioDB: портреты исполнителей

**Проверено:** бесплатный API v1 принимает тестовый ключ `123`. Поиск исполнителя возвращает максимум один результат; бесплатный уровень ограничен 30 запросами в минуту. В документации не уточняется, привязан ли лимит к IP, ключу или аккаунту. Тестовый запрос `search.php?s=coldplay` вернул артиста и портрет; изображение ответило `200 image/jpeg`.

Сейчас Tempo ищет изображение вручную и сохраняет его только после подтверждения пользователем. Для автоматического заполнения согласована такая политика:

- запускать поиск только для исполнителя без изображения;
- принимать только точное совпадение имени, без нечёткого подбора похожих артистов;
- не заменять изображение, уже назначенное или сохранённое пользователем;
- хранить выбранную картинку локально.

Условия TheAudioDB запрещают публиковать приложение в магазине без платной подписки. До распространения Tempo через магазин нужно повторно проверить актуальные условия и применимость лицензии. Локальное использование API само по себе не означает, что такое распространение разрешено.

Источники: [ограничения бесплатного API](https://www.theaudiodb.com/free_music_api), [условия использования](https://www.theaudiodb.com/docs_terms_of_use.php).

## SoundCloud: станция Wave и waveform

**Проверено на публичном треке:** неофициальный API сайта вернул `waveform_url`, `station_urn`, пять похожих треков и 50 элементов station-плейлиста. Это станция, собранная вокруг выбранного трека; она не использует историю или рекомендации аккаунта пользователя.

Интегратор Tempo получает `client_id` со страницы SoundCloud и вызывает приватный `api-v2.soundcloud.com`. Это работает без входа пользователя в рамках проверенного запроса, но endpoint не является стабильным публичным контрактом: SoundCloud может менять параметры, доступ и лимиты. Официальное руководство описывает `GET /tracks/{track_urn}/related` и `GET /system-playlists/{urn}`; проверка без OAuth на `api.soundcloud.com` получила `401`. Официальные запросы требуют OAuth. Client Credentials тоже требуют `client_secret`, который нельзя безопасно встраивать в desktop-приложение.

Для будущего режима **Wave** можно начать станцию от текущего SoundCloud-трека, использовать её элементы, а при отсутствии станции запросить похожие треки. В очередь следует добавлять только доступные для воспроизведения треки и не допускать повторов. Персональную ленту пользователя этот механизм не создаёт.

Текущий waveform-плеера не считывает звук: высоты столбиков псевдослучайно вычисляются из seed. SoundCloud предоставляет `waveform_url` — PNG с изображением формы волны, размер в проверенном примере 1800×280; это визуальный ресурс, а не аудиоданные. Для Waveform в Tempo следующий этап — отображать полученное изображение SoundCloud, а для локальных и скачанных файлов один раз декодировать аудио, вычислять пики и сохранять их в локальный кэш. Пока данных waveform нет, показывать обычную полосу прогресса.

Источники: [руководство SoundCloud API](https://developers.soundcloud.com/docs/api/guide), [изменения API](https://github.com/soundcloud/api/releases), [объяснение SoundCloud waveform](https://developers.soundcloud.com/blog/waveforms-let-s-talk-about-them/).

## YouTube Music через yt-dlp

Замеры выполнены с управляемым `yt-dlp 2026.08.19`. Время зависит от сети и текущего ответа YouTube Music; это ориентир для данного запуска, а не гарантия скорости.

| Операция | Результат | Время |
| --- | --- | ---: |
| Поиск 6 песен | Сами результаты поиска | 2,66 с |
| Получение метаданных 4 песен | Второй проход после поиска | 7,45 с |
| Поиск 8 альбомов | Плоский список коллекций | 2,97 с |

Наблюдаемые причины задержек в текущем коде:

- метаданные песен извлекаются отдельным проходом после поиска;
- очередь обогащения ждёт завершения процесса `yt-dlp`, прежде чем отдать его вывод интерфейсу, и обрабатывает песни последовательно группами до четырёх;
- поиск коллекций возвращает мало полей, поэтому карточки отдельно раскрываются, чтобы получить названия и метаданные;
- у плоского поиска коллекций нет названий, но он уже может содержать миниатюру; если её не передать в карточку, изображение появляется только после дополнительного запроса;
- отмена обогащения сейчас не останавливает процесс: PID не регистрируется для активного запроса.

Слепо включать `player_skip` не следует: параметры extractor могут убрать метаданные, необходимые плееру. Следующий этап оптимизации — показывать миниатюры из поиска сразу, измерить время до первой карточки, затем отдельно улучшать отмену процессов и конкурентность запросов, сверяя полноту возвращаемых полей.

### Обложки коллекций

Для проверенного альбома yt-dlp вернул варианты `mqdefault.jpg`, `sddefault.jpg` и `maxresdefault.jpg`: первые два URL ответили `200`, последний — `404`. Прежний код выбирал последнюю миниатюру и отбрасывал изображение, доступное в раннем элементе выдачи. Теперь карточка сохраняет раннюю миниатюру и список доступных вариантов, а интерфейс пробует их по очереди, если загрузка текущего URL завершилась ошибкой.

Источники: [документация опций yt-dlp](https://github.com/yt-dlp/yt-dlp/blob/master/README.md#extractor-arguments), [релизы yt-dlp](https://github.com/yt-dlp/yt-dlp/releases).
