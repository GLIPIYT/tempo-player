# Непрерывные персональные рекомендации

Дата: 03.10.2026, Asia/Yekaterinburg.

Основа: отчёт в чате «Отчёт: непрерывные рекомендации для Tempo», после которого пользователь запросил реализацию этой системы. Документ фиксирует решения для реализации. Численные пороги — стартовые параметры, не результаты измерения качества.

## Цель

Продолжать выдачу SoundCloud-рекомендаций по мере просмотра и прослушивания; распознавать повторные загрузки одной записи; учитывать действительные предпочтения, язык и разнообразие. Сохранять профиль локально между запусками, ограничивать сеть, память и фоновый анализ.

## Ограничения работы

- Работа и тематические коммиты только в существующем checkout, ветка `main`, с push. Ветки и worktrees не создаются.
- Ручные и визуальные проверки выполняет пользователь. Не добавлять и не запускать тестовые наборы без отдельного запроса. Проверки реализации: TypeScript, Rust, production build, lint изменённых файлов и diff.
- Сохранить текущую компоновку Home, drag-and-drop, действия кэширования и существующие источники лирики.
- Получение кандидата не создаёт библиотечную запись и не скачивает аудио. Автоматический кэш не считается положительной реакцией.
- После изменений оставить Vite и Tauri dev player запущенными.

## 1. Общий сервис и выдача

Один сервис принадлежит приложению и обслуживает Home и радио; React-hook только подписывается на его snapshot. Reservoir кандидатов, опубликованные карточки и очередь проигрывателя — разные коллекции.

- Цель reservoir: 100 уникальных подходящих кандидатов, пополнение при остатке ниже 30, публикация по 20.
- Начальная публикация не ждёт наполнения всего reservoir. Один цикл выполняет максимум 6 страниц; пустой источник закрывается после 3 страниц без новых подходящих записей.
- Один in-flight цикл, не более 2 HTTP-запросов одновременно, между стартами не менее 800 мс. Запросы явно вызванного поиска вне рекомендаций этим сервисом не блокируются.
- При 429 сохранять retryAt и уважать серверный reset/Retry-After; при отсутствии данных применять 30/60/120/300 секунд с jitter. Ручной retry не обходит cooldown. 401/403 допускают одно обновление web client ID, 429 его не обновляет.
- Сохранять продолжение отдельно для каждого исходного трека. Проверять HTTPS, host `api-v2.soundcloud.com` и ожидаемый endpoint; удалять старый client_id и вставлять текущий через URL query API. Повторный cursor не запрашивать.
- Related — основной источник, station — запасной при пустой/исчерпанной выдаче. Station stubs разрешать ограниченными batch-запросами. После исчерпания переключать исходные треки, затем ограниченный поиск по подтверждённым артистам/жанрам.
- Кэш страницы действует 24 часа, ошибки не кэшируются как успешные пустые страницы. Показанные карточки при обновлении профиля не переставляются.
- Удалить лимит 48. Оставлять до 300 карточек в текущем DOM-окне; старые можно удалить только после ухода пользователя вперёд, с компенсацией scrollLeft. История показов сохраняется независимо от DOM.
- При отсутствии подходящих источников показывать короткое состояние исчерпания; бесконечно повторять пустые запросы или подмешивать произвольные треки нельзя.

## 2. Исходные песни и разнообразие

Исходные песни выбираются с весом: 60% устойчивые положительные предпочтения, 25% недавний интерес, 15% положительно принятые открытия. При отсутствии группы её доля распределяется между доступными группами. Первая сессия опирается на лайки и старую историю с пониженной уверенностью; сырые playCount/skipCount не считаются достоверным вкусом.

- Исключать дубли исходных записей, ограничивать доминирование одного исполнителя.
- Для non-SC исходника сопоставлять название, исполнителя, версию и длительность. Первый результат поиска без достаточного совпадения не используется.
- Новая найденная запись становится источником расширения только после положительного слушания/явного действия. Непрослушанные кандидаты не создают бесконтрольную рекурсивную цепочку.
- Стартовое смешение выдачи: 75% близкие предпочтения, 15% соседние интересы, 10% открытия. Доли задают приоритет, а не требуют заполнения неподходящими песнями.
- После ранжирования — последовательный выбор с ограничением до 2 песен одного исполнителя на 10, разные исходные источники и разнесение версий одной композиции. При дефиците кандидатов ослаблять разнообразие, сохраняя запрет уверенных дублей.

## 3. Метаданные и дубли

SoundCloud DTO дополнить optional-полями: uploaderId, uploaderName, metadataArtist, genre, tags, description, bpm, isrc. Отсутствующие поля не выдумываются. Для интерфейса сохраняется исходное название; канонизация нужна для сопоставления.

Identity включает исходное/нормализованное название, исполнителя и уверенность, uploader отдельно, длительность, версию и canonical recording group.

- Unicode NFKC, регистр, пробелы, кавычки и тире нормализуются. Удаляются отдельные рекламные приписки, но сохраняются remix/live/slowed/sped-up/cover/instrumental/acoustic/edit.
- `Artist — Title` разбирается с учётом metadata_artist и словаря известных артистов; сомнительный разбор не переписывает библиотечные метаданные.
- Один upload ID — точный дубль. Совпадение подтверждённого исполнителя, специфического названия, версии и длительности с допуском max(2 секунды, 1% меньшей длительности) — сильное совпадение. Неизвестная длительность не является совпадением.
- Короткие/числовые названия, неоднозначные алиасы и одно сходство названия не дают автоматического объединения. Такие кандидаты ограничиваются мягким штрафом/разнесением.
- Разные версии сохраняются отдельно; точные копии одной версии получают общую группу. После подтверждения аудио объединение переносит историю показов/реакций на всю группу.
- Представитель группы выбирается по возможности полного воспроизведения и уверенности метаданных; обложка/популярность — вторичные признаки. Остальные uploads сохраняются как fallback при недоступности представителя.

## 4. Показы и повторения

Показ учитывается только при одновременно видимом разделе Home и карточке: intersection >= 50%, непрерывно 750 мс, document.visibilityState = visible. Префетч с rootMargin показом не считается. Записи батчатся.

В одной сессии группа записи повторно не публикуется. Между сессиями показ даёт cooldown 7 дней; два подтверждённых ранних пропуска за 30 дней — 14 дней. Явный отрицательный выбор, если будет добавлен позже, имеет отдельное постоянное исключение. Ручное воспроизведение доступных треков этими ограничениями не блокируется.

Радио исключает текущую очередь, уже сыгранные группы и недавно пропущенные записи, но использует собственные reservations: показы на Home не должны делать всю опубликованную полку недоступной радио.

## 5. Достоверное слушание

Новая сессия привязывается к звучащему media, а не к изменяемому queue.current. Начало, происхождение выбора, wall listening time, объединение реально пройденных аудиоинтервалов, playbackRate, причина окончания сохраняются по уникальному session ID.

- Учёт работает только при подтверждённом playing и продвижении media. Паузы, buffering, seek и смена media epoch исключаются. Повторное прослушивание участка увеличивает реальное время, но не unique coverage.
- Сохранять ранние пропуски, включая <10 секунд. Ошибка, отсутствие воспроизведения, восстановление очереди и автопредзагрузка не создают положительной реакции.
- Почти дослушанный трек, вручную переключённый дальше, не получает сильного отрицательного сигнала. Завершение после seek к концу не означает полного слушания.
- Песня <15 секунд получает ограниченный вес; завершения коротких звуков сами по себе не делают их основными исходными треками.
- Повторные запуски ограничены по вкладу одной записи в день. Лайк/ручной playlist-add сильнее автопроигрывания. Ручное кэширование — слабый сигнал, автоматическое — нулевой.
- Crossfade учитывает исходящую и входящую сессии отдельно до конца fading media. Stream-to-cache hotswap сохраняет сессию.
- Идемпотентные checkpoints не реже 15 секунд; финализация при select/next/previous/clear/end/error и реальном выходе. Close-to-tray продолжает слушание. При аварийном выходе остаётся checkpoint, без выдуманного окончания.
- Связанная запись listening_history создаётся один раз при финализации, actual wall seconds используются для минут, unique coverage — для completion. Старые записи сохраняются, но имеют низкую уверенность для вкусов.
- Очистка истории удаляет сессии/реакции и производный профиль; лайки остаются доступными явными предпочтениями.

## 6. Язык и ранжирование

Использовать небольшой локальный текстовый детектор `franc-min`; загрузка моделей и новые обязательные запуски Whisper отсутствуют. Анализировать уже полученную оригинальную лирику, включая поздние результаты и ручной источник, с исключением явно отмеченных переводов. Результат — распределение языков, evidence, confidence и hash текста.

- Для текста <80 букв — unknown. Для более длинного текста использовать несколько блоков и согласие результатов; score детектора не объявляется вероятностью.
- Название — вспомогательная информация с низкой уверенностью; алфавит, язык интерфейса и страна uploader не определяют язык вокала.
- Смешанные песни хранят несколько языков. Instrumental подтверждается отдельной меткой источника; отсутствие текста не доказывает инструментальность.
- Языковой профиль взвешивается положительным интересом, уверенностью и давностью. Unknown учитывается отдельно и не штрафуется как иностранный язык.
- Общий профиль: 70% устойчивый интерес с half-life 45 дней, 30% текущая сессия. При малом количестве достоверных событий снижается уверенность, избегая сильных выводов.
- Поиск использует исходники всех подтверждённых любимых языков. Язык влияет мягко на порядок; основной язык обычно выше, менее частые остаются в выдаче. Очень подходящая песня вторичного языка может опережать слабо подходящую основного.
- Жанр, теги, tempo и version preferences используются при наличии данных. Оценка энергию/настроения не выдумывает; нет данных — признак нейтрален.

## 7. Локальное хранение и акустическая проверка

Отдельный Rust store через публичный Db::with_conn, без HTTP/декодирования под DB mutex. Таблицы: listening sessions, recommendation impressions, features/recording aliases, provider page cache, bounded feed state. Ключ трека работает до появления библиотечной строки: soundcloud:<id>, youtube:<id>, local:<dbId>.

Retain: feedback 180 дней с агрегацией старого положительного интереса, impressions 30 дней, успешные provider pages 24 часа, metadata для последних 5000 кандидатов. Checkpoint/feed writes serial, revision исключает перезапись новым состоянием старого async результата. JSON и batches проверяются по размеру и числу элементов. Полный текст лирики не копируется в новый журнал: сохраняются hash и языковые признаки.

Для content fingerprint применять Rust `rusty-chromaprint` и потоковый локальный декодер `symphonia`. Нет скачивания чужих файлов для проверки дублей и новой внешней бинарной зависимости. Анализируется максимум 90 секунд существующего local/cache файла, один job, через общий analysis lane; отмена, wall budget и yields ограничивают нагрузку. Признаки и несовместимость кодека кэшируются по identity файла.

Совпадение отпечатка подтверждает одинаковую запись только при достаточной длине совпадения, низком bit error, близкой длительности и совместимой версии. Sped-up/remix/live не объединяются с оригиналом автоматически. При отсутствии файла или неподдерживаемом кодеке действует осторожный metadata-дедуп.

## 8. Интерфейс

Сохранить существующую полку и её кнопки; добавить автодозагрузку у правого края и короткие состояния loading/retry/exhausted. Существующие стрелки остаются справа. Отдельной кнопки «Радио» нет: это автоматическое продолжение очереди, когда текущая очередь закончилась и повтор выключен. «Воспроизвести все» запускает опубликованные рекомендации. Home и radio используют один reservoir, но независимые курсоры потребления; выбор другого трека отменяет неподходящий запрос продолжения.

Сохраняются кеш-статусы, drag-and-drop, контекстные действия и Play all. Отдельный курсор/канонический ID в provenance переносится при преобразовании, cache hotswap и сохранении очереди. Поздний ответ не дописывает очередь после ручного выбора/очистки.

## Риски, которые проверяются в реализации

- Слабые и числовые названия не скрывают разные песни; remix и оригинал сохраняются.
- Ошибки/seek/быстрые skip не обучают профиль как положительное слушание.
- Пагинация отсутствует/зациклена/429: переключение источников и cooldown без request storms.
- Неизвестный/смешанный язык не исключает кандидатов.
- Раздел вне viewport, radio, reload и восстановление очереди не создают двойных показов/сессий.

## Источники для зависимостей и API

- [SoundCloud public API specification](https://github.com/soundcloud/api/blob/master/openapi/api.yaml); поведение public API не переносится автоматически на web API-v2.
- [franc](https://github.com/wooorm/franc): текстовое определение языка, ограничения коротких текстов.
- [rusty-chromaprint](https://github.com/darksv/rusty-chromaprint): акустические отпечатки и сопоставление.
- [Symphonia](https://github.com/pdeljanov/Symphonia): Rust-декодер аудиоформатов; неподдерживаемые форматы остаются без отпечатка.
